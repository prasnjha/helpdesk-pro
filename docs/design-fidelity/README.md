# Design fidelity evidence

Each page that has a Stitch mockup has two files here: `<page>-mockup.png`, copied from `specs/design/mockups/`, and `<page>-built.png`, a full-page Playwright screenshot of the running dev app.

- **Viewports.** The mobile mockups are 780 px wide (2x of 390 px), so their built shots were taken at 390 px. The desktop mockups are 2560 px wide (2x of 1280 px), so their built shots were taken at 1280 px. All shots use device scale factor 1.
- **Data.** The shots use the seeded demo data (`backend/scripts/seed_demo_tickets.py`). A few KB articles, replies and a note were added through the existing API so the pages are not empty. Ticket titles carry the seed's `[DEMO]` prefix.
- **Extra shots.** There is no mockup for `admin-dashboard-built.png`, so it follows DESIGN.md and the admin console style. `mobile-nav-drawer-built.png` shows the AppShell nav drawer open at 375 px.

Tokens (colours, type, spacing, radius, elevation) come from `specs/design/DESIGN.md` Sections 1–4. They are defined as CSS custom properties in `frontend/src/styles/tokens.css`. Inter is self-hosted through `@fontsource-variable/inter`.

## App-wide differences

- **Shell.** Every signed-in page shares one AppShell: a header with the logo, "HelpDesk Pro", the username, the role and a Log out button, plus a 240 px role-based sidebar. Below 1024 px the sidebar becomes an overlay drawer opened from a menu button (DESIGN.md 3 and 5.6). The mobile mockups show a bottom tab bar instead (Tickets / Knowledge / Status / Profile). That bar was not built because the brief asked for a top menu on mobile, and "Status" and "Profile" have no routes.
- **Sidebar links.** The sidebar only lists routes that exist. Customers see My tickets, New ticket and Knowledge Base. Agents see Agent Queue and Knowledge Base. Admins see Dashboard, SLA policies and Knowledge Base. The mockups also show My Claimed, All Tickets, Analytics and Settings; these were not built because those routes don't exist.
- **Header extras.** Global search, the notification bell and the Available/Online switch are not built. They are global features that are not in the spec or the component map.
- **Preview-state switchers** are not built on any page (component-map.md ignore list).
- **Existing text and labels kept.** Wording that tests assert on is unchanged, for example "Agent workbench", "Knowledge base", "Admin console", "Replies", "History" and "Reply". Status, priority and SLA values are shown exactly as the backend returns them (`PENDING_CUSTOMER`, `ON_TRACK`, and so on); tests compare that text exactly. Only CSS changes the case.
- **Status chip colours.** DESIGN.md 1.3 has four rows. OPEN uses Open/Triage blue, IN_PROGRESS uses amber, RESOLVED uses emerald. PENDING_CUSTOMER and CLOSED use neutral slate, because red is reserved for breaches (DESIGN.md 5.7). SLA badges use emerald for ON_TRACK, amber for AT_RISK and rose for BREACHED.

## Pages without a mockup

- **Admin dashboard** (`admin-dashboard-built.png`): uses the admin console heading, a period card (From / To / Refresh), and three table cards: open by queue, breached by priority, and escalations in period. All three stay real `<table>`s for the tests.
- **KB editor**: styled like the new-ticket form card. No screenshot here.

## Responsive checks

- **Overflow.** No horizontal overflow was measured (`scrollWidth - innerWidth = 0`) on any page at 375, 390, 768 or 1280 px.
- **Queue table below 768 px.** Rows turn into stacked cards with labelled cells.
- **Detail pages below 1024 px.** The two-column layout becomes one column.
- **Snapshots.** The Playwright visual baselines in `frontend/e2e/snapshots/` (375 / 768 / 1280) were regenerated on Linux for this restyle.
