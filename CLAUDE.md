# HelpDesk Pro

B2B support ticketing and SLA management platform (capstone BC-AINE-007). Customers create tickets; a rules-based routing engine assigns them to team queues; agents claim, reassign, note and reply; tickets move through enforced status transitions; an SLA engine tracks timers in integer minutes and escalates breaches; resolved tickets publish to a knowledge base; admins manage versioned SLA policies. Synthetic seed data only.

## Project Constraints

- No hand-written production code. All code is generated by agents.
- The spec is the source of truth. Acceptance criteria AC-01..AC-10 each need a test named with its AC id.
- Roles (customer, agent, admin) are enforced at the controller layer.
- History, notes, assignments and SLA events are append-only.
- SLA timers are integer minutes only, never float.

## Quick Reference

**Backend:** `cd backend && uv run pytest -x -q` | `uv run ruff check --fix .` | `uv run mypy src/` | `uv run lint-imports`
**Frontend:** `cd frontend && npm test` | `npm run lint` | `npm run typecheck`
**E2E:** `cd frontend && npx playwright test`
**Full stack:** `./init.sh`, then start servers per `project-manifest.json` (API :8000, UI :5173)

## Architecture

Strict layered architecture: Types/Models → Config → Repository → Service → API → UI.
Business rules live in `src/domain`. One-way dependencies only, enforced by import-linter.
See `.claude/architecture.md` for full rules.
